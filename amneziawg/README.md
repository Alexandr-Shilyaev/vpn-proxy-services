# AmneziaWG (backend)

Backend протокола **AmneziaWG 3.1** — WireGuard с обфускацией для обхода DPI.
Часть проекта [vpn-proxy-services](../README.md); управляется общим ботом из `../bot`.

## Скрипты

| Скрипт | Назначение |
|--------|------------|
| `install_server.sh` | установка пакетов и `amneziawg` из PPA, ключи сервера, обфускация, `awg0.conf`, NAT, форвардинг, служба `awg-quick@awg0` |
| `add_user.sh <имя>` | ключи клиента, свободный IP, peer на лету, `.conf` + QR. Печатает `CONF=… QR=…` |
| `del_user.sh <имя>` | снимает peer, чистит конфиг, удаляет файлы. Печатает `DELETED=…` |
| `list_users.sh` | список клиентов и статус последнего хендшейка |
| `migrate.sh` | смена формата обфускации (например 2.0 → 3.1) без потери клиентов |
| `lib/common.sh` | общие функции: генерация параметров, рендеринг конфигов, проверка версий |

Три «пользовательских» скрипта (`add`/`del`/`list`) — и есть контракт, который вызывает бот.
`migrate.sh` — административная операция, запускается руками.

## Установка

Обычно ставится из корня проекта одной командой:

```bash
sudo ../setup.sh --token <BOT_TOKEN> --admins <id> --protocols amneziawg
```

Либо только сервер протокола, вручную:

```bash
sudo ./install_server.sh                 # значения по умолчанию (формат 3.1)
sudo ./install_server.sh --port 443 --subnet 10.8.0 --dns 1.1.1.1,1.0.0.1 --ip <публичный_IP>
```

`install_server.sh`:

- ставит/**обновляет** `amneziawg` + `amneziawg-tools` из официального PPA `ppa:amnezia/ppa`
  до последней версии (повторный запуск тянет апгрейд);
- проверяет, что **сборки `amneziawg-tools` и `amneziawg-dkms`** не старее нужной для
  выбранного формата (3.1 → `>= 20260812`, 2.0 → `>= 20250901`), и иначе останавливается
  с инструкцией по обновлению;
- дополнительно **проверяет сам модуль ядра**: создаёт временный интерфейс и пробует задать
  параметры выбранного формата. Это ловит случай, когда пакет обновлён, а в ядре остался
  старый модуль (DKMS не собрался под текущее ядро);
- по умолчанию генерирует **обфускацию формата AmneziaWG 3.1** (см. раздел ниже);
  `--awg2` — формат 2.0, `--legacy` — старый 1.x;
- создаёт `/etc/amnezia/amneziawg/awg0.conf` с заданным **MTU** (по умолчанию 1280);
- включает IPv4-форвардинг и NAT (iptables MASQUERADE), а при `--ipv6` — ещё IPv6-форвардинг и NAT66;
- запускает `awg-quick@awg0`, состояние хранит в `/etc/awg-vpn/`.

Опции:

| Флаг | Назначение |
|------|------------|
| `--port <n>` | UDP-порт (51820) |
| `--subnet <a.b.c>` | IPv4-подсеть /24 (`10.8.0`) |
| `--dns <list>` | DNS клиентов (`1.1.1.1, 1.0.0.1`) |
| `--mtu <n>` | MTU интерфейса и клиентов (1280; меньше из-за обфускации) |
| `--ip <addr>` | публичный IP/домен (иначе автоопределение) |
| `--iface <name>` | имя WG-интерфейса (`awg0`) |
| `--subnet6 <p>` | IPv6 ULA-префикс /64 (`fd0a:1ce5:c0de`) |
| `--ipv6 auto\|on\|off` | туннелировать IPv6 (`auto`: включается, если IPv6 есть у сервера) |
| `--awg3` | формат обфускации AmneziaWG 3.1 — **по умолчанию** |
| `--awg2` | формат 2.0 (имитация протокола, CPS) — для клиентов 2.0 |
| `--legacy` | формат 1.x (для старых клиентов «AmneziaWG Legacy») |

> Не забудьте открыть **UDP-порт** (по умолчанию 51820) у провайдера/в облаке.

Формат существующего сервера повторный запуск `install_server.sh` **не меняет** — иначе
все выданные конфиги разом перестали бы работать. Для смены формата есть `migrate.sh`.

### MTU, IPv6 и DNS

- **MTU** задаётся явно (1280) — лечит частую проблему «подключается, но сайты не грузятся».
  Для 3.1 Amnezia рекомендует именно 1280 (в их приложении дефолт 1376 приходится понижать).
- **IPv6** в режиме `auto` включается только если у сервера есть глобальный IPv6 на внешнем
  интерфейсе. Если IPv6 нет, клиентам выдаётся только `0.0.0.0/0` — без `::/0`, чтобы IPv6-трафик
  не уходил в «чёрную дыру» и не было утечки реального адреса.
- **DNS** можно переопределить на конкретного клиента: `add_user.sh alex --dns 9.9.9.9`.

## Управление вручную

```bash
sudo ./add_user.sh alex                 # клиент + .conf и QR
sudo ./add_user.sh bob --dns 9.9.9.9    # свой DNS для клиента
sudo ./add_user.sh bob --mtu 1320       # свой MTU для клиента
sudo ./del_user.sh alex                 # удалить
sudo ./list_users.sh                    # список
```

Файлы клиента: `/etc/awg-vpn/clients/<имя>/` (`<имя>.conf`, `<имя>.png`).

## Обфускация: 3.1 vs 2.0 vs Legacy

Параметры обфускации должны **полностью совпадать** у сервера и у каждого клиента, поэтому
генерируются один раз при установке и хранятся в `/etc/awg-vpn/server.env`.

| Формат | Что делает | Клиенты |
|--------|------------|---------|
| **3.1** (по умолчанию) | всё из 2.0 + шифрование заголовков, паддинг контента, рандомные тайминги, случайные хвосты handshake | 3.1+ |
| **2.0** (`--awg2`) | имитация протокола (CPS-пакет `I1`), заполнение `S1–S4`, динамические заголовки `H1–H4` | 2.0+ |
| **1.x** (`--legacy`) | только junk-пакеты и заполнение — «просто шум» | любые |

### Что именно добавляет 3.1

| Параметр | Назначение | Как генерируется |
|----------|------------|------------------|
| `HeaderProtectionKey` | шифрует заголовок пакета (тип/индексы) ChaCha20 — DPI больше не видит даже типы сообщений WG | случайные 32 байта base64 |
| `ContentPaddingAddition` | случайные байты внутри шифротекста вместо выравнивания WG по 16 байт — ломает «ступенчатую» гистограмму размеров | диапазон `0-<16..48>` |
| `RekeyAfterTime`, `RekeyTimeout`, `RejectAfterTime`, `KeepaliveTimeout`, `MaxHandshakeAttempts` | таймеры становятся **диапазонами**: модуль берёт случайное значение на каждое срабатывание, исчезает периодичность | вокруг штатных 120/5/180/10/18 |
| `RandomTrailers` | случайные хвосты в handshake-пакетах | `on` |
| `PersistentKeepalive` (у клиента) | тоже диапазон: ровный пульс каждые 25 с сам по себе был сигнатурой | `18-30` |

Три требования формата, которые установщик соблюдает автоматически — если править конфиг
руками, их легко нарушить:

1. **`S1–S4 ≥ 12`.** При Header Protection первые 12 байт префикса служат nonce для ChaCha20;
   модуль отвергает конфиг с меньшим значением (`S1 must be more then 12 to use headerProtection`).
2. **`S1 = S2 = S3 = S4`** при включённом `RandomTrailers` (требование документации Amnezia).
3. **`H1–H4 = 1,2,3,4`.** В 1.x/2.0 их рандомизируют, т.к. заголовок идёт открытым текстом;
   в 3.1 он шифруется, и документация предписывает оставить совместимые значения.
4. **Верх `RekeyAfterTime` ниже низа `RejectAfterTime`** — иначе сессия может быть отброшена
   раньше, чем произойдёт перегенерация ключей.

> ⚠️ Формат 3.1 **несовместим** с клиентами 2.0 и наоборот: `HeaderProtectionKey` и
> `RandomTrailers` обязаны совпадать с двух сторон, иначе handshake не проходит.

## Переход с 2.0 на 3.1 (migrate.sh)

Обновить формат «на месте» нельзя: нужен новый набор параметров обфускации и перевыпуск
всех клиентских конфигов. `migrate.sh` делает это, **не теряя пользователей** — ключи
клиентов, их IP и peer'ы на сервере сохраняются, пересобираются только файлы `.conf` и QR.

```bash
sudo ./migrate.sh --to v3        # 1.x/2.0 -> 3.1
sudo ./migrate.sh --to v2        # вернуться на 2.0 (если клиенты не обновить)
sudo ./migrate.sh --regen        # сменить сами значения параметров, не меняя формат
sudo ./migrate.sh --to v3 --yes  # без подтверждения
```

Что происходит:

1. проверяются версии `amneziawg-tools` / `amneziawg-dkms` — до любых изменений;
2. в `/etc/awg-vpn/backup/<дата>-<старый формат>/` складывается бэкап `server.env`,
   `awg0.conf` и каталога клиентов;
3. генерируются новые параметры, перезаписывается `[Interface]` (секции `[Peer]` переносятся
   как есть), перевыпускаются все клиентские `.conf` и `.png`;
4. служба перезапускается целиком (не `awg syncconf`: часть параметров уровня устройства
   нельзя снять на живом интерфейсе);
5. если служба не поднялась — **автоматический откат** из бэкапа, старые конфиги снова валидны.

После миграции **раздайте клиентам новые `.conf`/QR** — старые не подключатся. Файлы уже
лежат в `/etc/awg-vpn/clients/<имя>/`, достаточно переслать их заново.

> Если порт в `awg0.conf` правился вручную, а в `server.env` — нет, скрипт это заметит и
> предупредит: `[Interface]` пересобирается из `server.env`.

## Клиент

Конфиг и QR содержат параметры обфускации, поэтому импортируйте их в приложение
**AmneziaWG / Amnezia VPN**. Обычный (ванильный) WireGuard к серверу с обфускацией
**не подключится**.

### Минимальные версии для формата 3.1

| Платформа | Клиент | Версия |
|-----------|--------|--------|
| Windows | [amneziawg-windows-client](https://github.com/amnezia-vpn/amneziawg-windows-client/releases) | **3.1.0+** (возьмите сборку под свою архитектуру: `amd64`, для ARM-ноутбуков `arm64`) |
| Android | [amneziawg-android](https://github.com/amnezia-vpn/amneziawg-android/releases) | **v3.1.20260814+** |
| iOS / macOS / десктоп | [Amnezia VPN](https://github.com/amnezia-vpn/amnezia-client/releases) | **5.0.1.5+** |
| Linux | `amneziawg` + `amneziawg-tools` | сборка **≥ 20260812** (как на сервере) |
| Роутеры (OpenWRT/Keenetic и пр.) | — | 3.1 **не поддерживается**; для них ставьте сервер с `--awg2` |

Импорт: **Import tunnel(s) from file** → выберите `.conf` → **Activate**. QR удобен для телефона,
на десктопе импортируйте файл `.conf`.

> Ошибка Windows-клиента **«You must use the native version of WireGuard on this computer»** —
> это **не про конфиг**, а про архитектуру: скачана сборка под другой процессор. Возьмите `amd64`
> (или `arm64`) под вашу Windows.

## Устранение неполадок

**На WiFi/проводе работает, на мобильной сети «не удалось установить соединение» (нет handshake).**
Мобильный оператор режет UDP или порт `51820`. Переведите сервер на **443/udp** (его пропускают
почти всегда — там живёт QUIC):

```bash
sed -i 's/^ListenPort = .*/ListenPort = 443/' /etc/amnezia/amneziawg/awg0.conf
sed -i 's/^WG_PORT=.*/WG_PORT="443"/'        /etc/awg-vpn/server.env
ufw allow 443/udp 2>/dev/null || true
systemctl restart awg-quick@awg0
# пересоздать клиента, чтобы в .conf попал новый порт:
./del_user.sh phone && ./add_user.sh phone
```

> Меняйте порт **в обоих файлах** — `awg0.conf` и `server.env`. Иначе следующий запуск
> `migrate.sh` пересоберёт `[Interface]` из `server.env` и вернёт старый порт (скрипт
> предупредит о расхождении).
>
> ⚠️ Откройте **UDP-порт и в облачном firewall хостера** (security group панели VPS) — он
> **отдельный** от `ufw`. Это частая причина, почему порт «закрыт снаружи».

При установке с нуля можно сразу задать порт: `install_server.sh --port 443` (или `setup.sh --port 443`).

**Handshake есть, но интернета нет** — это MTU. Снизьте в клиентском `.conf` `MTU = 1280` → `1200`
(если надо — `1100`), либо для всех новых клиентов: `sed -i 's/^WG_MTU=.*/WG_MTU="1200"/' /etc/awg-vpn/server.env`.

**Даже на 443/udp не подключается на мобильной** — оператор глушит **весь UDP**. AmneziaWG (UDP)
такое не обходит; нужен TCP-протокол на 443 — **VLESS + Reality** (в роадмапе проекта как «база»).

**Служба `awg-quick@awg0` не стартует после установки.** Скорее всего модуль/утилиты старее
выбранного формата. Проверьте, что стоит:

```bash
dpkg-query -W amneziawg-dkms amneziawg-tools   # для 3.1 нужны сборки >= 20260812
dkms status amneziawg                          # должен быть 'installed' для текущего ядра
```

> `cat /sys/module/amneziawg/version` для диагностики формата **не годится**: модуль собирается
> с `WIREGUARD_VERSION=1.0.0` из Makefile и всегда показывает `1.0.0` независимо от версии
> протокола. Судить можно только по версии deb-пакета и по `dkms status`.

Обновите пакеты:

```bash
sudo apt-get install --only-upgrade -y amneziawg amneziawg-tools amneziawg-dkms
```

…либо переустановите в совместимом режиме: `install_server.sh --awg2` (или `--legacy`).

**«Загруженный модуль AmneziaWG не принял параметры формата…»** — это предполётная проверка
(`probe_awg_support`): скрипт создал временный интерфейс, скормил ему пробный конфиг и получил
отказ. Значит версия пакета новая, а в ядре работает прежний `.ko` — почти всегда DKMS не
собрался под текущее ядро. Ничего при этом не меняется, сервер остаётся рабочим. Лечение:

```bash
sudo apt-get install -y "linux-headers-$(uname -r)"
sudo dkms autoinstall
sudo modprobe -r amneziawg && sudo modprobe amneziawg
```

Если модуль под это ядро вообще не собирается — загрузитесь в ядро, где он собран, либо
оставайтесь на `--awg2`.

**Клиенты не подключаются именно после перехода на 3.1** — почти всегда старая версия
приложения (см. таблицу минимальных версий). Если обновить клиентов нельзя:
`sudo ./migrate.sh --to v2`.

**Модуль не собирается DKMS** — нужны `linux-headers-$(uname -r)` и ядро, на котором модуль
3.x собирается (сборки `v3.0.20260731-*` не собирались на ядрах старее 6.7; в PPA уже 3.1).
На OpenVZ/LXC-VPS модуль ядра поставить нельзя — нужен KVM.
