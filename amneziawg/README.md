# AmneziaWG (backend)

Backend протокола **AmneziaWG 2** — WireGuard с обфускацией для обхода DPI.
Часть проекта [vpn-proxy-services](../README.md); управляется общим ботом из `../bot`.

## Скрипты

| Скрипт | Назначение |
|--------|------------|
| `install_server.sh` | установка пакетов и `amneziawg` из PPA, ключи сервера, обфускация, `awg0.conf`, NAT, форвардинг, служба `awg-quick@awg0` |
| `add_user.sh <имя>` | ключи клиента, свободный IP, peer на лету, `.conf` + QR. Печатает `CONF=… QR=…` |
| `del_user.sh <имя>` | снимает peer, чистит конфиг, удаляет файлы. Печатает `DELETED=…` |
| `list_users.sh` | список клиентов и статус последнего хендшейка |
| `lib/common.sh` | общие функции |

Эти три «пользовательских» скрипта (`add`/`del`/`list`) — и есть контракт, который вызывает бот.

## Установка

Обычно ставится из корня проекта одной командой:

```bash
sudo ../setup.sh --token <BOT_TOKEN> --admins <id> --protocols amneziawg
```

Либо только сервер протокола, вручную:

```bash
sudo ./install_server.sh                 # значения по умолчанию
sudo ./install_server.sh --port 51820 --subnet 10.8.0 --dns 1.1.1.1,1.0.0.1 --ip <публичный_IP>
```

`install_server.sh`:
- ставит/**обновляет** `amneziawg` + `amneziawg-tools` из официального PPA `ppa:amnezia/ppa`
  до последней версии (повторный запуск тянет апгрейд — старый 1.x-модуль формат 2.0 не примет);
- для формата 2.0 нужна сборка tools ≥ **2025-09-01** (релиз AmneziaWG 2.0) — установщик проверяет
  **дату сборки deb-пакета** `amneziawg-tools` (не `awg --version`: тот всегда показывает базовую
  дату форка `1.0.20210914`) и при старой версии останавливается с инструкцией либо предлагает `--legacy`;
- по умолчанию генерирует **обфускацию формата AmneziaWG 2.0** (имитация протокола: `I1` + `S1–S4`,
  динамические заголовки `H1–H4`, junk-пакеты `Jc/Jmin/Jmax`); с `--legacy` — старый формат 1.x
  (`Jc, Jmin, Jmax, S1, S2, H1–H4`) для совместимости со старыми клиентами;
- создаёт `/etc/amnezia/amneziawg/awg0.conf` с заданным **MTU** (по умолчанию 1280);
- включает IPv4-форвардинг и NAT (iptables MASQUERADE), а при `--ipv6` — ещё IPv6-форвардинг и NAT66;
- запускает `awg-quick@awg0`, состояние хранит в `/etc/awg-vpn/`.

Опции:

| Флаг | Назначение |
|------|------------|
| `--port <n>` | UDP-порт (51820) |
| `--subnet <a.b.c>` | IPv4-подсеть /24 (`10.8.0`) |
| `--dns <list>` | DNS клиентов (`1.1.1.1, 1.0.0.1`) |
| `--mtu <n>` | MTU интерфейса и клиентов (1280; меньше из-за обфускации) |
| `--ip <addr>` | публичный IP/домен (иначе автоопределение) |
| `--iface <name>` | имя WG-интерфейса (`awg0`) |
| `--subnet6 <p>` | IPv6 ULA-префикс /64 (`fd0a:1ce5:c0de`) |
| `--ipv6 auto\|on\|off` | туннелировать IPv6 (`auto`: включается, если IPv6 есть у сервера) |
| `--legacy` | старый формат обфускации 1.x (для старых клиентов «AmneziaWG Legacy»); по умолчанию — формат 2.0 |

> Не забудьте открыть **UDP-порт** (по умолчанию 51820) у провайдера/в облаке.

### MTU, IPv6 и DNS

- **MTU** теперь задаётся явно (1280) — лечит частую проблему «подключается, но сайты не грузятся».
  Поднять можно `--mtu 1320`, если канал позволяет.
- **IPv6** в режиме `auto` включается только если у сервера есть глобальный IPv6 на внешнем
  интерфейсе. Если IPv6 нет, клиентам выдаётся только `0.0.0.0/0` — без `::/0`, чтобы IPv6-трафик
  не уходил в «чёрную дыру» и не было утечки реального адреса.
- **DNS** можно переопределить на конкретного клиента: `add_user.sh alex --dns 9.9.9.9`.

## Управление вручную

```bash
sudo ./add_user.sh alex                 # клиент + .conf и QR
sudo ./add_user.sh bob --dns 9.9.9.9    # свой DNS для клиента
sudo ./add_user.sh bob --mtu 1320       # свой MTU для клиента
sudo ./del_user.sh alex                 # удалить
sudo ./list_users.sh                    # список
```

Файлы клиента: `/etc/awg-vpn/clients/<имя>/` (`<имя>.conf`, `<имя>.png`).

## Обфускация: 2.0 vs Legacy

По умолчанию сервер генерирует **формат AmneziaWG 2.0**: вместо «просто шума» туннель имитирует
начало реального протокола (механизм CPS, сигнатурный пакет `I1`) + универсальное заполнение
(`S1–S4`) и динамические заголовки (`H1–H4`). Это сильнее против поведенческого DPI, чем 1.x.

> ⚠️ Формат 2.0 **несовместим** со старыми клиентами — нужен **AmneziaWG / Amnezia VPN 2.0+**.
> Старые клиенты покажут такой профиль как «AmneziaWG Legacy» и не подключатся.
> Если клиенты обновить нельзя — ставьте сервер с `--legacy` (формат 1.x).
>
> Также: для 2.0 нужен **модуль/утилиты AmneziaWG ≥ 2.0** на сервере (из PPA). Если служба
> `awg-quick@awg0` не стартует после установки, установщик подскажет переключиться на `--legacy`.

## Клиент

Конфиг и QR содержат параметры обфускации, поэтому импортируйте их в приложение
**AmneziaWG / Amnezia VPN** (для формата по умолчанию — версии **2.0+**). Обычный (ванильный)
WireGuard к серверу с обфускацией **не подключится**. Для совместимости с ванильным WG обнулите
параметры обфускации и у сервера, и у клиента.
